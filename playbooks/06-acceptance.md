# 手册 06 · 验收清单

> **agent 说"建好了"不算数。** 这份清单是一道闸门：建完服务后逐条过，
> **每条都要贴原始输出，不许只说"通过了"。**

---

## 为什么要有这份清单

**agent 说“服务建好了”，用 subagent 独立跑一遍整个流程，测输出是否符合预期。**

没有这道独立复测，容易漏的是这些：

- 跑过一次，但没验状态机（只验了最顺的那条路）
- 验了状态，但没验下载是不是真的能下
- 全都验了，但**没注意到它往不许写的地方写了东西**

> 实测教训：某次从零建的服务，自测做得相当完整（8 个任务、五档状态、下载、重启恢复都验了），
> 但**漏了一条**——Python 加载源脚本时在旁边生成了 `__pycache__`，写进了声明为只读的目录。
> 那是靠事后翻文件才发现的。**验收清单里就有"只读约束核验"这一条，本该当场抓到。**

---

## 清单

### A. 服务起得来

- [ ] 启动日志原文（`Uvicorn running on http://…` 那几行），**不是"启动成功"四个字**
- [ ] 监听地址与端口和约定一致（**`0.0.0.0` 意味着内网可达，要确认这是有意为之**）

### B. 机读面

- [ ] `GET /docs` 打开是 **Scalar**，不是原生 Swagger
- [ ] `GET /openapi.json` 能拉到
- [ ] `fetch_schema.py` 体检报告原文，看四个数：接口数 / 有 description 的 / 有说明的参数 / 有结构的响应
- [ ] **没有 API 之外的路由混进 schema**（返回 HTML 的 `/` 等应 `include_in_schema=False`）

### C. 用户面

- [ ] `build_console.py` 生成时 **JS 语法检查通过**（它会自动做，失败会报）
- [ ] **`CONF.read.*` 逐个验**：喂**真实接口返回**给每个取值函数，确认都取到值、没有 `undefined` / 空串
      - 重点四个：`progress` / `now` / `counts` / `artifacts`（手册 02 §三 还有 `id` / `summary`）
      - **没有浏览器也要做**：把 CONF 从 HTML 里抠出来用 node 执行，DOM 层验不了，数据层必须验
- [ ] 界面能通过 HTTP 取到（`GET /` 返回 200 + 合理字节数）

### D. 真跑一个任务（**不能用假数据**）

- [ ] 任务跑通，贴**子进程的真实 stdout 片段**
- [ ] 终态正确、耗时、产物数量与总大小
- [ ] 结果真的落在约定的输出根下（**贴路径**）
- [ ] 进度轨迹**单调不回头**（把轮询到的 progress 序列贴出来）

### E. 状态机覆盖

尽量把每一档都造出来（造不出就说明为什么）：

- [ ] `done`（全部成功）
- [ ] `partial_failed`（有成功也有跳过/失败）
- [ ] `failed`（一个都没成功）
- [ ] `invalid`（扫不到可处理的单元）
- [ ] `cancelled`（运行中取消）
- [ ] 错误分支：输入不存在 → 400；任务 id 不存在 → 404

### F. 结果交付

- [ ] 单文件下载：HTTP 200 + 字节数 + `Content-Disposition`
- [ ] 打包下载：HTTP 200 + zip 条目数 + **目录层级没被拍平**
- [ ] `?rel=../../../<某个服务文件>` → **404**（路径穿越要挡得住）

### G. 持久与恢复

- [ ] 重启服务后，历史任务还在（贴 `GET /api/tasks` 的返回）

### H. ★ 只读约束核验（最容易漏）

- [ ] 声明为只读的目录/文件，**SHA256 与 mtime 都没变**（贴出来比对）
- [ ] **扫一遍那些目录有没有新增文件**——`__pycache__`、临时文件、日志都可能被顺手写进去
      - 特别注意：Python 用 `importlib` 按路径加载模块时会在**源文件旁边**写字节码缓存。
        要用 `sys.dont_write_bytecode = True` + 子进程 `-B` + `PYTHONDONTWRITEBYTECODE=1` 挡
- [ ] 服务自己该写的地方（输出根/日志）确实写了，没写到别处

### I. 收尾

- [ ] 没有遗留的后台进程（贴端口检查结果）
- [ ] 没有遗留的临时文件
- [ ] 交付出去的东西能独立启动（换台机器、拷目录）

---

## 怎么用这份清单

1. **建完就过一遍**，不要等交付前才补
2. **清单交 subagent 独立执行**——主对话只收结论 + 原始输出，过程留在子 agent 的上下文里
3. **每一条贴原始输出**——命令 + 输出，不要转述
4. **过不了的条目不要跳过**——**返回交互提问**，说清是哪一条、卡在哪、需要什么条件
   （比如浏览器侧交互验不了，就问要不要装浏览器，或者由他判断放行），确认后完善
5. 清单本身也可以按服务再加条目（比如有流式响应就加一条“断线重连”）

> **这条规矩不是形式主义**：本次实测里，正是"贴原始输出"这个要求，
> 让 agent 自己把只读区的 `__pycache__` 翻了出来 —— 它本来可以只说一句"全部通过"。
