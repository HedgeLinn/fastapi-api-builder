# 手册 05 · 界面那份说明（给终端用户看）

> **两份说明，不是一份。** 对象不同，讲的东西不同，写法也不同。
> 这一节讲给**终端用户**看的那一份怎么写、写在哪。
> 状态：方法是实践中的结论；示例取自一份完整的服务文案。

---

## 一、两份说明的分工

| | `/docs`（给**接口调用方**） | 界面（给**终端用户**） |
|---|---|---|
| 讲什么 | 怎么调用、参数是什么、怎么传参 | 怎么用、输入是什么、输出是什么、结果在哪看 |
| 写法 | 接口语言：`file: UploadFile`、multipart、curl 示例 | 业务语言：「上传一个文件」「跑完去共享盘取」 |
| 写在哪 | 源码的 `docstring` / `description` | **界面里，就地**（见第二节） |
| 谁看 | 技术人员 | 不写代码的同事 |

**唯一真正共享的是事实**——参数有几个可选值、默认是哪个、必填不必填。但**说法各写各的**：

```
/docs      输出格式，默认 CSV
界面       想拿到哪种文件格式，默认 CSV
```

同一件事，两拨人要问的问题根本不一样：技术人员问"这个字段是 multipart 还是 JSON"，同事问"我那个 Excel 到底传哪个"。

---

## 二、界面那份说明写在哪

**不单独成文，写在使用它的地方。** 对应到两个界面模板的 `CONF`：

| 位置 | 写什么 | CONF 字段 |
|---|---|---|
| 页面顶部 | 这个服务是干什么的（一句话） | `lede` / `tagline` |
| 输入框上方 | 这一步要做什么 | `form.heading` |
| 输入框下方 | **该填什么、怎么填、最容易填错什么** | `form.desc` / `form.howto` |
| 确认页 | 要跑多久、能不能关页面、结果会去哪 | `confirmNote` |
| 运行中 | 现在在干什么；**为什么没动静是正常的** | 模板生成 + `text.step3Sub` |
| 结果页 | 结果在哪、怎么拿、能不能给别人 | `text.step4OkSub` |
| 出错时 | 人话解释 + 下一步怎么办 | `msg.*` / 后端返回的 `error` 原文 |

**为什么就地写**：终端用户不会先读一份说明再用界面。说明必须出现在他正好需要它的那一秒。

## 三、四类必须写的说明

### ① 一句话说清"这是什么"

```
✗ 示例分析服务 · 提交任务 · 实时进度 · 结果下载
✓ 选一个数据目录，跑完去共享盘取结果。
```

后者说的是**用户能得到什么**，前者说的是**系统有哪些功能**。

### ② 输入怎么填（**最容易漏、也最值钱**）

示例服务的真实例子 —— 它的目录层级有两种填法，填错会导致整批任务失败：

> **不知道填哪个？**
> · 只分析一个市：填那个市自己的目录
> · 一次分析多个市：填它们**上一级**的目录，服务会逐个处理
> 两种情况服务都会自动识别，**填错它会告诉你原因**。

三个要点：**给判断依据**（不是给规则）、**给两种典型填法**、**承诺会报错**（让人敢填）。

### ③ 为什么要等这么久

示例服务的例子：

> 每次任务都要重新加载 numpy/scipy/matplotlib，**约 10 秒无输出属正常**。

**沉默是最劝退的。** 告诉用户"这段时间没动静是正常的"，比加一百个进度动画都有用。

### ④ 结果在哪、怎么拿

```
✗ 产物已生成
✓ 结果已经存到共享盘：\\x.x.x.x\...\示例市_2026年09月18日
  也可以在这里下载到本机。
```

**给完整路径**——同事之间传结果，靠的就是这个路径，不是你的下载按钮。

## 四、写作规矩

**① 用业务语言，不用接口语言**

| 不要 | 要 |
|---|---|
| 提交任务 | 开始分析 |
| 输入根目录 | 要分析的数据目录 |
| 产物 / artifacts | 结果文件 |
| `task_id` | （界面上不出现） |
| `partial_failed` | 部分完成：有几个地方没跑成 |
| `404 Not Found` | 没找到这个任务，可能已经被清理了 |

**② 说"你会遇到什么"，不说"系统会做什么"**

**③ 不写废话**：不要"请点击下方按钮开始"——按钮就在那儿。

**④ 就地一两句**，不展开成长文。要展开的放「怎么用」的折叠区里（两个模板都有位置）。

**⑤ 后端的错误原文要透传**，但可以加一句人话前缀：

```
✗ 输入根目录不存在或不可访问
✓ 没找到这个目录（服务端返回：输入根目录不存在或不可访问）。确认一下路径，或者找管理员看看权限。
```

## 五、界面外的那份（可选，但推荐）

终端用户第一次用的时候，通常不是在界面里学，而是在聊天窗口里收到一段话。给服务开发人员一段现成的：

```
【示例分析】服务上线了，地址：http://10.57.52.187:80xx/

怎么用：填一个数据目录 → 点开始 → 等 20~30 秒 → 结果自动存到共享盘，
        也可以直接在页面上打包下载。

填哪个目录：只分析一个市就填这个市；要一次跑多个市，填它们上一级。
            填错了服务会告诉你怎么回事，不会白跑。

跑的时候可以关掉页面，后台会继续跑。
有问题看页面下方的运行日志，或者找我。
```

**三句话：怎么用 / 填什么 / 出问题怎么办。**

## 六、检查清单

- [ ] 页面顶部有一句话说明「用户能得到什么」（不是「系统有什么功能」）
- [ ] 输入框下方说清了**该填什么**和**最容易填错什么**
- [ ] 如果任务有沉默期，明确写了"多久没动静是正常的"
- [ ] 结果页给了**完整路径**，不只给下载按钮
- [ ] 全部文案过了一遍"业务语言"的替换表，没有残留的接口术语
- [ ] 后端的错误信息透传了，并且加了人话前缀
- [ ] 没有"请点击""请输入"这类废话
